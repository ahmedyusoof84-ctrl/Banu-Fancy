# Publish Smart Retail for free

The `render.yaml` Blueprint uses a free Render Docker web service and requires a separate persistent PostgreSQL database. Render's free web filesystem is temporary. Its own free PostgreSQL databases expire after 30 days, so do not use one for live shop records. A free Neon PostgreSQL project is one option; check its current limits before using it for business data. Free services can sleep, pause at usage limits, or change their terms. Keep independent backups.

1. Create a free PostgreSQL project at [Neon](https://console.neon.tech/) and copy its **direct** connection string with SSL enabled. Keep it private. Select a region close to the Render web service if available.
2. In [Render](https://dashboard.render.com/), create a **Blueprint** from the public GitHub repository using `render.yaml`. The Blueprint is configured with `plan: free`; verify the plan on Render's confirmation screen. Enter the Neon connection string as `DATABASE_URL`. Enter a new administrator email and a strong, unique password in the private `ADMIN_EMAIL` and `ADMIN_PASSWORD` prompts. Render generates `JWT_SECRET`. Do not put any of these values in GitHub.
3. After the deploy finishes, visit the assigned `https://...onrender.com/api/health` URL and sign in. `REQUIRE_PERSISTENT_DB=true` prevents startup if `DATABASE_URL` is missing. Render supplies `RENDER_EXTERNAL_URL` for the application's HTTPS origin check.
4. To transfer existing shop data, download a fresh backup from local Settings and restore it in the hosted Settings page. Restoration replaces the new database and signs everyone out. Sign in with the original administrator credentials from the restored data, then verify product counts, stock, a sample invoice, and Reports totals.
5. Save regular backups outside Render. The free web service's automatic backup files disappear when it restarts or sleeps. The database is persistent, but the app's backup status alone does not mean an off-site copy exists. Do not enter transactions in both local and hosted shops after migration.

The public app URL exists only after Render creates the web service. Do not mistake `127.0.0.1` for an internet address or publish the local `.env`, `data`, `LOCAL-ACCESS.txt`, or backup JSON files.
